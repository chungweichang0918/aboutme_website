## 背景

複数ゾーンの農業モニタリングには、実務上の課題が 3 つあります。センサーの値が更新されなくなったとき、画面の数値がいつ計測されたものかを知る必要があります。ゾーンごとに正常な推移が異なるため、同じしきい値ですべての変化を説明するのは困難です。また、水ポンプなどの設備は現場に直接影響するため、起動条件、権限、停止の仕組みを明確に設計する必要があります。

そこで、センシング、データの解釈、設備操作を一つの管理フローにまとめました。管理者はまずデータを確認し、そのうえでシステムの提案を採用するかどうかを判断できます。

## 担当範囲

ESP32-S3 によるセンシングと制御、Raspberry Pi ゲートウェイ、FastAPI バックエンド、Vue の管理画面、ローカル AI による解説まで、システムの設計・実装・統合を一人で担当しました。

通信断の後に再送されるデータは元の計測時刻を保持するため、管理者は画面の値がまだ有効かどうかを判断できます。灌水のポンプ停止条件は現場の ESP32 が判定します。これらのフローは、ゾーンごとのセンサーデータと灌水操作の記録で検証しました。

## 現場ノードから管理画面まで

| 構成要素 | 役割 |
| --- | --- |
| ESP32-S3 センサーノード | 空気、光、土壌に関する計測を収集します。制御機能を持つゾーンでは水ポンプなどの設備を接続できます。 |
| Raspberry Pi ゲートウェイ | MQTT でノードのデータを収集します。オフライン時は一時保存し、再接続後に元の計測時刻を保ったまま再送します。 |
| FastAPI と統計分析 | データ照会と制御の承認を提供します。EWMA と CUSUM により、ゾーン・センサーごとのベースラインに対する統計的な偏りの観察を補助します。 |
| Vue 管理画面 | ゾーンごとの値、データソース、計測時刻、期限切れ状態、履歴推移を表示し、権限のあるユーザーが設備操作を審査できます。 |
| Mac 上のローカル AI | RAG による出典付きの解説と画像認識フローを提供します。設備への指令は独立した承認フローで処理します。 |

## データの解釈と設備制御

管理画面ではデータソースと計測時刻を明示します。データが古くなった場合は期限切れの表示を残し、現場データ、履歴値、シミュレーションデータをそれぞれ確認できるようにしています。

設備操作は、まず権限のある担当者が承認し、その後に現場ノードが実行します。灌水フローのポンプ停止条件は ESP32 側で判定し、設定条件に達すると現場で停止できます。AI の解説は、情報の整理と根拠の説明に用います。

## 検証範囲

展示資料には、ゾーンごとのセンシングと 2 種類の灌水フローを記録しています。A ゾーンでは、条件到達後にノードがポンプを停止したことを現場のシリアルログで確認しました。B ゾーンには、提案から人による承認、起動、停止までの操作記録があります。これらの記録は指定したフローの確認に用いたもので、長期的な安定性、季節をまたぐ性能、農業上の効果は別途検証が必要です。

現場ログ、合成シナリオ、画像のホールドアウトテストはそれぞれ個別に評価しており、各結果には固有のデータソースと適用範囲があります。
