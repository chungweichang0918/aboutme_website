## 專案背景

多區農業監控有三個實際問題。感測讀值停止更新時，使用者需要知道畫面上的數字量測於何時。不同區域的正常走勢可能不同，同一組門檻很難解釋所有變化。水泵等設備會影響現場，因此啟動條件、授權與停機機制都需要明確設計。

我把感測、資料判讀與設備操作整合到同一個管理流程。管理者可先核對資料，再決定是否採用系統建議。

## 個人貢獻

我獨立負責系統設計、實作與整合，涵蓋 ESP32-S3 感測與控制、Raspberry Pi 閘道、FastAPI 後端、Vue 管理工作台，以及本地 AI 解說。

我讓斷線補送的資料保留原始量測時間，讓管理者能辨認畫面上的數值是否仍有效。灌溉停泵條件由 ESP32 在現場判斷。我用分區感測與灌溉操作紀錄驗證這些流程。

## 從現場節點到管理工作台

| 元件 | 用途 |
| --- | --- |
| ESP32-S3 感測節點 | 收集空氣、光照與土壤相關量測。具控制能力的區域可接水泵等設備。 |
| Raspberry Pi 閘道 | 透過 MQTT 收集節點資料。斷網時暫存，恢復連線後補送，保留原量測時間。 |
| FastAPI 與統計分析 | 提供資料查詢與控制授權。EWMA 與 CUSUM 依各區、各感測器的基線輔助觀察統計偏移。 |
| Vue 管理工作台 | 顯示分區讀值、資料來源、量測時間、過期狀態與歷史趨勢，讓有權限的使用者審核設備操作。 |
| Mac 本地 AI | 透過 RAG 提供附來源的解說，另有影像辨識流程。設備指令由獨立的授權流程處理。 |

## 資料判讀與設備控制

管理介面會標示資料來源與量測時間。遇到過期資料時，畫面會保留過期提示，讓現場資料、歷史讀值與模擬資料可以各自核對。

設備操作先由有權限的人員核准，接著由現場節點執行。灌溉流程的停泵條件在 ESP32 端判斷，達到設定條件時可在本機停止。AI 解說則用於整理資訊與說明依據。

## 驗證範圍

展示材料記錄了分區感測和兩種灌溉流程。A 區有現場序列顯示節點在達到條件後停泵。B 區有從提出建議、人工核准、啟動到停泵的操作紀錄。這些紀錄用來確認指定流程，長期穩定性、跨季表現和農業效益仍需另外驗證。

現場紀錄、合成情境與影像留出測試各自評估。每一類結果都有自己的資料來源與適用範圍。
